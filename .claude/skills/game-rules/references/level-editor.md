# Level editing, custom levels and editor state (Modules.Levels)

Rules of the level editor and of custom level storage. Core game rules are in `../SKILL.md`, the editor UI in `../../blazor-ui/references/level-editor.md`.

Contents: Level editing rules · Custom levels · Level editor state

## Level editing rules (pure functions in `Levels`)

- `LevelLimits` adds `MaxStrawberries` = 10, `MaxPizzas` = 10 (`LevelValidator` reports `TooManyStrawberries`/`TooManyPizzas` for every level), `MaxCustomLevels` = 20 and `MaxSteps` = 1000 (mirrors `ProgramLimits.MaxExecutedSteps`; a Game test keeps them equal, Levels must not reference Game).
- `LevelSolver` (Domain, static): `ShortestSolution(Grid) -> int?` runs one BFS from the start (and, with `RequireAllItems`, one from every strawberry); it returns `null` at once when the goal or a needed strawberry is unreachable, otherwise a dynamic programme over (set of strawberries, last strawberry) finds the cheapest visiting order (a strawberry on the goal cell counts as visited at the end). Without `RequireAllItems` it is the plain goal distance; passing the goal earlier does not end the run (same rule as the interpreter). Pizzas never count. `CanReachGoal(Grid)` ignores items. Target (NFR2): the check on every editor change takes at most 200 ms; `LevelPerformanceTests` measures `LevelCheck.Evaluate` on 20x20 with 10 strawberries spread over the board (median of 5 runs, output with `--output detailed`) and loading 20 such custom levels (about 0.6 ms and 18 ms, a plain BFS over (cell, mask) took about 25 ms and 480 ms). A test compares the solver with a state-space BFS on 300 random grids.
- `LevelEditing` (Domain, static, immutable `LevelDefinition` in, new one out, never throws for user input): `NewLevel(id, name)` (10x10, start (0,9), goal (9,0)), `FromTemplate`, `Apply(level, EditorTool, Position) -> EditResult(Level, EditHint)`, `SetRequireAllItems`, `Resize -> ResizeResult(Level, RemovedCount)`, `ClearObjects`, `NextDefaultNumber(names, format)`, `CleanName`, `UniqueName(name, existingNames)` (import only: the name when free, otherwise « (2)», « (3)» … with the smallest free number, ordinal comparison, base cut so the result stays within `MaxNameLength` without splitting a surrogate pair), `ExportFileName(name)` (lowercase ASCII `[a-z0-9-]`, ä/ö/ü/ß to ae/oe/ue/ss, accents dropped, at most 40 characters, empty gives `level`, a reserved Windows device name (con, prn, aux, nul, com1-9, lpt1-9) gets the prefix `level-`, plus `ExportExtension` `.heropath.json`; M5 S5).
  - `EditorTool`: `Start`, `Goal`, `Tree`, `Rock`, `Pond`, `Strawberry`, `Pizza`, `Eraser`. An obstacle or item replaces whatever is on the cell, the same tool on the same content removes it. `Start`/`Goal` move there and remove the object on the cell. Refused clicks return the same level instance plus an `EditHint` (`StartOnGoal`, `GoalOnStart`, `ObstacleOnStart`, `ObstacleOnGoal`, `ItemOnStart`, `TooManyStrawberries`, `TooManyPizzas`); an item on the goal is allowed; `Eraser` never touches start or goal; a cell outside the grid changes nothing (`EditHint.None`).
  - Removing the last strawberry (also by resize, replace, or moving start/goal onto it) switches `RequireAllItems` off; `SetRequireAllItems(true)` needs a strawberry.
  - `Resize` clamps to 3..20, removes objects outside (counted), clamps start and goal to the new border; if the goal then equals the start or sits on an obstacle it moves to the nearest free cell (BFS order up, down, left, right), an object under the start is removed (counted). The result always passes `LevelValidator` (except the name).
  - `CleanName` uses `TextCleaner.Clean` (Shared; `TextCleaner.IsHidden(char)` is the shared test for control, format and line/paragraph separator characters) and cuts to `MaxNameLength` UTF-16 chars without splitting a surrogate pair.
- `LevelIdGenerator.NewId(exists)` (Application, because it is random): `custom-` plus 12 lowercase hex characters from `RandomNumberGenerator`, drawn again on collision.
- `LevelCheck.Evaluate(level) -> LevelCheckResult(Errors, Status, MinimumSteps)` (the editor goes through an internal `LevelCheckCache`: the solver only runs again when the `Grid` differs from the last one, so typing a name only re-validates) with `LevelCheckStatus` `Valid`, `Invalid`, `GoalUnreachable`, `StrawberriesUnreachable`, `TooManySteps` (shortest solution above `MaxSteps`; an overload takes the limit for tests). `CanSave` = `Valid`. `MinimumSteps` is the shortest solution when one exists.
- `TextCleaner.Clean(raw, maxTextElements)` (Shared): control, format and line/paragraph separator characters removed, trimmed, cut to text elements, trimmed again, empty when nothing is left. `HeroChoice.NormalizeName` uses it and falls back to the default name.

## Custom levels (LevelRepository, ICustomLevelStore)

- `IAppStorage.SetAsync`/`RemoveAsync` return `ValueTask<bool>` (`true` = written or removed, `false` = storage unavailable or full, nothing changed). Callers that only remember a preference (`LanguageService`) ignore it.
- `ICustomLevelStore` (`Levels/Application/Contracts`): `LoadAsync` and `SaveAllAsync(levels) -> bool`. `StorageCustomLevelStore` keeps all custom levels as one compact JSON array under `StorageKeys.CustomLevels` (`heropath.levels`), so every change is one write. Loading is untrusted-input handling and never throws: empty or whitespace, longer than 21 x `LevelJson.MaxJsonLength`, broken JSON, deeper than 16 or not an array give no levels; every element goes through `LevelJson.Read` and `LevelCheck.CanSave`, and an element is skipped when it is broken, manipulated, oversized, unsolvable (the solver is fast enough to check every element before the first render, 20 worst-case levels load in about 20 ms, so an unsolvable level is filtered at load and never offered), over the item limits, has no name or repeats an id; at most `MaxCustomLevels` are kept. Skipped entries disappear with the next save.
- `LevelRepository(store, standard, readLevel)` (scoped, `Levels/Application`; the standard list and `LevelJson.Read` are passed in by `AddLevelsModule`, because Application must not use Infrastructure): `Standard`, `Custom`, `All` (standard first), `Find`, `IsCustom`, `NextDefaultName(format)`, `LoadAsync` (once; a failing store means no custom levels; stored ids that equal a standard id are dropped), `SaveAsync(level) -> SaveOutcome` (`Saved`, `LimitReached`, `Invalid`, `StorageFailed`), `DeleteAsync(id) -> bool`, `ImportAsync(json, defaultNameFormat) -> ImportResult(Outcome, Level)` with `ImportOutcome` (`Imported`, `InvalidFile`, `NotSavable`, `LimitReached`, `StorageFailed`) and `Changed`.
  - `SaveAsync`: `Invalid` when `LevelCheck` cannot save the level, the name is `null` or the id is a standard id (checked before the limit); an existing id is overwritten in place, a new one is appended and refused at 20 (`LimitReached`).
  - `SaveAsync`, `DeleteAsync`, `ImportAsync` and `LoadAsync` run one after another behind a `SemaphoreSlim` (limit, duplicate and next-list checks happen inside it, so overlapping calls cannot lose an update; a change before the load first loads the stored levels; `Changed` is raised after the gate is released). Every change writes the whole new list to the store first and only then replaces the in-memory list (lists are replaced, never modified), so on `StorageFailed` memory and storage stay as they were and `Changed` is not raised. `Changed` fires only after a successful save, delete or import, and after a load that found at least one level.
  - `ImportAsync` never overwrites: a new id from `LevelIdGenerator` (the file's id is dropped), name cleaned with `LevelEditing.CleanName`, or the next free default name when the file has none, then made unique among the custom names with `LevelEditing.UniqueName` inside the gate (a second import of the same file becomes «Name (2)»; names typed in the editor may still repeat). An empty or blank name is an invalid file (the validator rejects it).
- A custom level always has a `Name` (user text, rendered only as text); standard levels have `null` and a resx name.

## Level editor state (LevelEditorState)

- `LevelEditorState(LevelRepository)` (scoped, `Levels/Application`, registered by `AddLevelsModule`) holds the level being edited so a language switch or any re-render keeps it: `HasDefaultName` (the name is still the generated default of a new unsaved level; cleared by `SetName`, a successful save and opening a saved level) with `RenameDefault(format) -> bool` (regenerates it in another language, keeps `IsDirty`, never touches a typed or saved name), `Draft` (`LevelDefinition`, name `""` rather than `null` while empty), `EditingId` (`null` until the draft is saved or when a saved level is opened), `Tool` (default `Tree`), `IsDirty`, `Hint` (`EditHint` of the last refused click), `RemovedCount` (things removed by the last resize), `LastSave` (`SaveOutcome?`), `IsSaving`, `Check` (`LevelCheckResult`, recomputed on every change), `CanSave` (`Check.CanSave` and not saving) and `Changed`.
- `OpenNew(defaultNameFormat)` (fresh `LevelIdGenerator` id and `LevelRepository.NextDefaultName`), `Open(id) -> bool` (custom levels only; unknown and standard ids return `false` and change nothing), `SelectTool`, `Apply(position)` (a refused click keeps the same draft instance and sets `Hint`), `Resize(w, h)` (clamped, same size is a no-op), `SetName(raw)` (`LevelEditing.CleanName`, empty name makes `Check` `Invalid`), `SetRequireAllItems`, `SaveAsync(ct) -> SaveOutcome`.
- `OpenTemplate(standardId, defaultNameFormat) -> bool` (an unsaved copy with a new id and the next free default name via `LevelEditing.FromTemplate`, not dirty, `false` for ids that are not standard levels), `ClearObjects()` (`LevelEditing.ClearObjects`; no-op on an empty level) and `DeleteAsync(id, defaultNameFormat, ct) -> bool` (repository delete; when the deleted level is the open one the editor starts a new clean level, a failed delete changes nothing).
- Messages (`Hint`, `RemovedCount`, `LastSave`) are cleared by the next change. The draft id never changes, so saving the same draft again overwrites. `SaveAsync` does nothing (returns `Invalid`) while the check forbids saving or another save runs (`Changed` is raised in a `finally`, so a cancelled save leaves `IsSaving` off), and a draft edited or replaced during the write is not marked clean: `IsDirty` is only reset when the saved instance is still the draft.
