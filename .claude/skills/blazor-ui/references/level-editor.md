# Level editor, managing levels, export and import (Levels.UI, Game.UI EditorPage)

Details for `/editor`. Core component rules are in `../SKILL.md`, the editor rules and state in `../../game-rules/references/level-editor.md`.

Contents: Level editor · Managing levels · Export and import (incl. the editor side panel layout)

## Level editor

- `GameBoard` edit mode: with a `CellClicked` handler (`EventCallback<Position>`) and optional `CellLabel` (`Func<Position,string>`) every cell is a `<button type="button" class="cell" data-testid="edit-cell-{x}-{y}">` with the same `data-kind`/`data-item` and graphics, an `aria-label`, no hero, no `cell-x-y` and no `item-x-y` ids (`data-editable="true"` on the board). Without the handler, and always in `Preview`, nothing changes. The editor sets `--board-cols`/`--board-rows` and `--hp-reserved: 11.75rem` on its board container; the board is at most 44 px per cell (20x20 on 1366x768 gives about 29 px, the documented exception to the 44 px rule), buttons override the global 44 px minimum for cells only.
- `EditorPage` (`Game.UI/Pages`, routes `/editor` and `/editor/{LevelId}`, test id `editor-page`, link `editor-back` to `""`) hosts `LevelEditor` (`Levels.UI/Components`, `data-testid="level-editor"`, parameter `LevelId`). The editor opens the level in `OnParametersSet` only when `LevelId` changes (an unknown or standard id starts a new level), so re-renders and language switches keep the draft; all state is `LevelEditorState`. Opening a level from the list or «Neues Level» navigates to `editor/{id}` or `editor` (relative) after opening it itself and remembers the id, so the parameter change does not open it again; the first save of a new draft replaces the URL with `editor/{id}`. String parameters of child components need `@` (`OpenId=".EditingId"`), otherwise Razor passes the text.
- Parts: `EditorToolbar` (`editor-tool-{start|goal|tree|rock|pond|strawberry|pizza|eraser}`, `aria-pressed`, active tool = thick frame plus check mark badge, icon `aria-hidden`), `EditorSizeControl` (`editor-width|height`, `-minus`, `-plus`, 44 px buttons, `<output>` with the number), `EditorStatus` (`editor-status`, `data-state` = `solvable|unsolvable|invalid`, `data-min-steps` only when solvable; solid, dashed and dotted frame plus glyph), `CustomLevelList` (`custom-level-list`, `custom-level-{id}` buttons with `aria-current` for the open level, `editor-new`). In `LevelEditor` itself: `editor-name` (input, `maxlength` 50, bound on `oninput` to a raw text field so a trailing space is not cut while typing; `aria-describedby` points at `editor-name-hint`), `editor-require-all` (disabled without strawberry, with a note), `editor-hint` (refused click or «N Dinge wurden entfernt»), `editor-save` (disabled unless `LevelEditorState.CanSave`, `aria-describedby` the reason `editor-save-reason`), `editor-saved` (`data-outcome` = `SaveOutcome` name).
- `StartPage` has `start-build` («Level bauen») below «Los!», navigating to `editor`. The start form (name, selection) is component state and is not kept across the trip to the editor.

## Managing levels

- `ConfirmDialog` (`Shared.UI/Components`, a `LocalizedComponentBase`): own modal, no `window.confirm`, no Fluent UI. Parameters `Visible`, `Title`, `Message` (plain strings, so level names stay text), optional `ConfirmLabel`/`CancelLabel` (defaults `Confirm_Yes` / `Confirm_Cancel` of `SharedResources`), `OnConfirm`, `OnCancel`. Renders nothing unless `Visible`; the parent owns the flag and closes it in its callbacks. `role="dialog"`, `aria-modal`, `aria-labelledby`/`aria-describedby`, test ids `confirm-backdrop`, `confirm-dialog`, `confirm-title`, `confirm-message`, `confirm-yes` (first button, `ElementReference.FocusAsync` when it opens), `confirm-no`. Escape (keydown on the backdrop) cancels, two invisible focusable sentinels around the dialog wrap Tab inside it, a click on the backdrop does nothing. Buttons are 44 px; the backdrop blocks the page (also the language switcher), so E2E switches the language before opening a dialog.
- `LevelEditor` keeps one pending question (`Pending`: new, template, open, delete, clear, leave) and shows one `ConfirmDialog` for it; the texts come from one lookup (`_questions`: `Pending` to the key prefix `Discard|Delete|Clear|Leave` and whether Cancel reads «Stay»), so the dialog keys are `Confirm_{Prefix}_Title|Message|Yes`. Hint, save and cell texts are mapped in the internal `EditorTexts` helper. New level, template and opening another level ask «discard changes?» only while `LevelEditorState.IsDirty`; delete (name as text) and clear always ask. `editor-template` is a native `<select>` (`` is bumped after every pick so the same template can be chosen again; options `editor-template-{id}` from `LevelRepository.Standard`), `editor-clear`, `custom-level-delete-{id}` (in `CustomLevelList`, event `DeleteRequested`), `editor-delete-failed` (storage failure), `editor-try` (only with an `OnTryOut` handler; saves with the save rules, raises `OnTryOut(levelId)` only after `SaveOutcome.Saved`).
- NavigationLock pattern (decision D6): `<NavigationLock OnBeforeInternalNavigation="BeforeNavigation" ConfirmExternalNavigation="false" />` in `LevelEditor`. The handler returns a `Task` (an `EventCallback` cannot take a `ValueTask`), does not await the dialog: when dirty it calls `context.PreventNavigation()`, remembers `TargetLocation` and sets the pending question. «Yes» stores the target as allowed (`_allowedTarget`) and calls `NavigateTo(target)`; the editor's own navigations (`GoTo`: URL replace after the first save, open, new; the exemption is only set when the URL really changes) and the callback of «Try it» (flag `_trying`) are exempt, a clean editor never asks, a reload is not guarded. **The allowance is consumed**: `BeforeNavigation` clears `_allowedTarget` on every navigation, whether it matches or not, so a later dirty navigation to the same URL asks again. bUnit's `BunitNavigationManager` supports `PreventNavigation`, so `LevelEditorTests` cover it.
- `EditorPage` handles `OnTryOut`: with `HeroChoice.IsChosen` `SelectLevel(id)` and `NavigateTo("play")`, otherwise `Preselect(id)` and `NavigateTo("#level-card-{id}")` (relative to the base href, so it is the start page with a fragment; every level card is a `<div id="level-card-{id}">`, and Blazor scrolls to the element, see «Fragment navigation» below). It subscribes to `LevelRepository.Changed` and replaces a deleted `HeroChoice.LevelId` by the first level of `LevelProgress`.
- Fragment navigation: Microsoft Learn «ASP.NET Core Blazor routing and navigation», section «Navigate to an element with a hashed (#) reference», documents that `NavigationManager.NavigateTo("/counter#targetElement")` and `<a href="/counter#targetElement">` navigate to the element with that `id` without custom JS (checked by E2E, the preselected card is in the viewport). `NavigationManager.GetUriWithFragment` is described there for the current URI but is not in the .NET SDK 10.0.401 reference assemblies, so plain `href="#custom-levels"` is used. The start page has `start-jump-custom` («Zu meinen Levels», 44 px link under the intro, only when custom levels exist, `href="#custom-levels"`) and the section `<section id="custom-levels">`. The custom section stays after the standard levels (FR21).
- `PlayPage` shows `play-edit` («Bearbeiten», 44 px) below the level picker only while `LevelRepository.IsCustom(level.Id)`; it navigates to `editor/{id}`.

## Export and import

- Export: `CustomLevelList` has `custom-level-export-{id}` per entry (event `ExportRequested`). `LevelEditor` writes the stored level with `LevelJson.Write` (id, name and grid only, never the hero name) and hands it to `IFileDownload.SaveTextAsync(LevelEditing.ExportFileName(name), json, ct)`. A `false` result shows `editor-export-failed`. `BrowserFileDownload` (host, scoped, `IAsyncDisposable`) loads `./js/file-download.js` lazily with `IJSRuntime.InvokeAsync<IJSObjectReference>("import", ...)`, passes the UTF-8 text as a `DotNetStreamReference` and returns `false` on `JSException`, `JSDisconnectedException` or `InvalidOperationException`. Pattern: Microsoft Learn «ASP.NET Core Blazor file downloads», section «Download from a stream».
- Import: `EditorLevelFiles` (`Levels.UI/Components`, `editor-level-files`) owns the whole file part: the `InputFile` (`Microsoft.AspNetCore.Components.Forms`, `accept=".json,application/json"`, `data-testid="editor-import"`, one file) inside a big `<label class="import-button">` (the input is transparent and stretched over the label, so it stays keyboard-focusable, focus ring via `:focus-within`, styling needs `::deep`), the import message, the export failure message, the export privacy hint and `ExportAsync(id)`, which `LevelEditor` calls through `@ref` when `CustomLevelList` raises `ExportRequested`. Parameter `DefaultName` (`Func<int,string>`). `OnChange` first checks `IBrowserFile.Size` against 256 KB, then reads with `OpenReadStream(256 KB)` as UTF-8 in a loop until EOF, up to `LevelJson.MaxJsonLength` chars (more is «Die Datei ist zu gross.»). `IOException`, `JSException`, `JSDisconnectedException`, `InvalidOperationException`, `UnauthorizedAccessException`, `NotSupportedException` and a cancellation that did not come from the component itself give «Die Datei konnte nicht gelesen werden.» (`Editor_Import_Unreadable`); only the component's own disposal token propagates. Then `LevelRepository.ImportAsync`. The outcome maps to `editor-import-message` (`data-state` `ok|error`; imported, invalid file, too large, unreadable, not savable, limit, storage failed). The message is kept as an enum, so it follows a language switch. The file name from the browser is never shown or used. The `InputFile` has an `@key` bumped after every import, so the same file can be chosen again. The import adds the level to the list and does not open it, the draft stays untouched, so no confirm dialog. A new import or export-failure message gets `tabindex="-1"` and takes the focus in `OnAfterRenderAsync` (`ElementReference.FocusAsync`, no custom JS), so the browser scrolls it into view inside the scrolling side column (bUnit: `JSInterop.VerifyFocusAsyncInvoke()`).
- `editor-export-hint` («Der Name deines Levels steht in der Datei. Verwende nicht deinen echten Namen.») sits under the list, next to the export buttons, and only while custom levels exist. `file-download.js` revokes the object URL one second after the click (`setTimeout`), the anchor is removed at once, so slow browsers can still start the download.
- Editor side panel layout: `editor-panel` has two columns that scroll **independently** (`.editor-column` has `max-height: calc(100dvh - 9rem)` and `overflow-y: auto`), so scrolling the long second column never moves the tools. Order of the second column: name, require-all, status, save/try, save message directly below the buttons, `CustomLevelList` (the saved entry is right under the message), export hint, `EditorLevelFiles`, template select. Rule: a result message must sit next to the button that caused it or take the focus; E2E checks it with `LayoutAssertions.AssertVisibleInEditorPanelAsync`.
- Scrolling column pattern: a column that scrolls inside a fixed-height panel (`.editor-column`) never cuts an element without a cue. It has bottom padding (1.75rem), `scroll-padding-block: 2rem` (the width of the edge fade, so a focus or `scrollIntoView` target lands outside the fade) and an edge fade: `mask-image` with the registered custom properties `--edge-top`/`--edge-bottom`, animated by `animation-timeline: scroll(self block)` inside `@supports (animation-timeline: scroll())` (no fade at the very top and bottom, so nothing is faded at rest at either end). Without that support the column falls back to «scroll shadows» (`background-attachment: local` cover gradients over `scroll` shadows). Message boxes that take the focus (`editor-saved`, `files-message`) carry `scroll-margin-block: 1rem`, so the whole box with some context lands inside. The name field, require-all, status, save buttons and save message are one `editor-group` block. Rule: never rely on a plain cut at the edge. A fade is not a layout fix: if everything should be visible without scrolling in the initial state, shorten the content instead.
- Editor fit: in the initial state (10x10, DE and EN, 1366x768) the second column fits without an internal scroll (`LayoutAssertions.AssertEditorColumnsFitAsync`: scrollHeight not above clientHeight, template select fully visible). The template select sits inside `CustomLevelList` (`ChildContent`, directly under the «Meine Levels» / «Neues Level» row, its label is visually hidden with `editor-sr-only`), the import section has no visible heading (hidden `h3` names the section), a 2.75rem button and a one-line hint. The document `lang` is a static `de` in `index.html` and does not follow the culture, so never rely on `hyphens: auto`. Tool labels (`.tool-name`) use `overflow-wrap: normal`, `word-break: keep-all` and 0.875rem, so a word like «Radiergummi» never breaks inside the word at 20x20 DE laptop (`AssertToolLabelsFitAsync`: no overflow, one line per one-word label).
